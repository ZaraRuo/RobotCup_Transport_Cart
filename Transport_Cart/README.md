# Transport Cart — 自动搬运机器人

基于 Arduino Mega 2560 的自动搬运机器人基础框架（内容与代码同步，以代码为准）。

## 硬件清单

| 硬件 | 数量 | 引脚 | 说明 |
|------|------|------|------|
| Arduino Mega 2560 | 1 | - | 主控板 |
| 步进电机 + 驱动器 | 2 | L: DIR30/PUL11/EN31, R: DIR32/PUL12/EN33 | 底盘后轮驱动（右轮软件方向反转） |
| 步进电机 + 驱动器 | 1 | DIR40/PUL41/EN42 | 转盘旋转（72°倍数） |
| 灰度循迹传感器 | 12路 | A0~A7(前8路), A8~A11(后4路) | 黑线检测 |
| 电动伸缩推杆 (L298N) | 1 | IN1=22, IN2=23, ENA=24 | 货物推放（伸/缩时长输入） |
| 二维码扫描模块 | 1 | Serial3(TX=14, RX=15), 9600bps | 自动输出模式（内容ASCII+CR） |
| 颜色传感器 | 1 | S0=50, S1=51, S2=52, S3=53, OE=49, OUT=2 | TCS230（8针），中断计数测频 |

说明：

- 步进电机 EN 引脚：HIGH=脱机/禁用，LOW=使能（初始化后为使能）。
- 推杆 L298N：`IN1=HIGH/IN2=LOW` 伸出，`IN1=LOW/IN2=HIGH` 缩回，`IN1=LOW/IN2=LOW` 停止；ENA 引脚由 MCU 输出 HIGH（全速使能）。
- 二维码模块为自动输出模式：扫码成功后自动发送 内容ASCII+回车(0x0D)，波特率 9600。例：扫"1"→`0x31 0x0D`，扫"5"→`0x35 0x0D`，10~16 为两位 ASCII（如扫"12"→`0x31 0x32 0x0D`）。按 CR/LF 分帧解析为整数（1~16）。
- 完整接线指南见仓库根目录 [`README.md`](../README.md#接线指南)。

## 车辆运动模型

```
          前 (行进方向)
          ┌─────────┐
          │ 万向轮  │ ← 无动力，仅支撑
          │         │
  ← 左    │  车 体  │    右 →
          │         │
     ┌────┤  ┌──┐   ├────┐
     │ M1 │  │  │   │ M2 │ ← 步进电机主动轮 (后)
     └────┤  └──┘   ├────┘
          │    ↑    │
          │  190mm  │
          └─────────┘
```

| 参数 | 值 | 来源 |
|------|-----|------|
| 车型 | 4轮差速 | 前2万向轮(无动力) + 后2步进主动轮 |
| 步距角 | 1.8° | 电机规格 |
| 细分数 | 32 | 驱动器设置 |
| 每圈步数 | **6,400** | 360÷1.8×32（`STEPPER_STEPS_PER_REV`） |
| 轮径 | 70mm | 实测 |
| 轮周长 | 219.91mm | π×70 |
| 每毫米步数 | **≈29.10** | 6400÷219.91（`WHEEL_STEPS_PER_MM`） |
| 后轮轮距 | 190mm | 实测（`WHEEL_BASE_MM`） |

### 旋转标定参考（基于 WHEEL_BASE_MM=190）

| 角度 | 每轮弧长 | 每轮步数 |
|------|---------|---------|
| 45° | 74.61mm | 2,171 |
| 90° | 149.22mm | 4,342 |
| 180° | 298.45mm | 8,684 |

旋转 1° 每轮步数 ≈ 48.25（π×190/360×29.10）。

## 调试模式

在 `Transport_Cart.ino` 顶部修改宏（代码当前默认值）：

```cpp
#define MAIN_DEBUG         1    // 1=调试, 0=正常工作
#define DEBUG_STAGE        10   // 选择调试阶段 (1~12)
#define DEBUG_MOTOR_BYPASS 0    // 1=电机旁路(只打日志不转)
```

### 调试阶段

| Stage | 名称 | 测试内容 |
|-------|------|---------|
| 1 | 推杆测试 | 伸到顶(10s)→伸到底(10s)，重复2次 |
| 2 | 传感器读数 | 12路原始值 + 前/后偏移量，每500ms一行 |
| 3 | 单电机测试 | 左轮/右轮独立正转3000步+反转3000步 |
| 4 | 底盘直行 | 前进300mm→后退150mm→旋转±90°，不循迹 |
| 5 | 前向循迹 | `trackForward(300000, 80)`，前8路循迹 |
| 6 | 后向循迹 | `trackBackward(10000, 80)`，后4路循迹 |
| 7 | 二维码扫描 | 同一接收路径，扫码/电脑串口模拟打印数字 (1~16) |
| 8 | 原地旋转测试 | CCW/CW各45°/90°/180°，标定 WHEEL_BASE_MM |
| 9 | 转盘测试 | 72°旋转 + 5仓位占用/定位演示 |
| 10 | 颜色识别 | TCS230 实时识别，串口 'w' 白平衡 |
| 11 | 转盘+颜色 | 车头仓转180°识别，'s'全仓扫描记录颜色 |
| 12 | 流程分段测试 | 复用正式流程同一套代码（运动函数/收料/识别/遮蔽） |

### 循迹修正算法

统一修正逻辑（前进/后退共用，`Chassis::_applyTracking()`）：

- 加权质心偏移量 -100~+100（`LineSensor::frontOffset()/backOffset()`）
- 偏移 ±25 内线性比例修正，超出直接满额修正
- 修正量由 `TRACK_MAX_CORRECTION_US`（默认 1000）控制
- 线偏右 → 减速右侧轮回正；线偏左 → 减速左侧轮（后退时左右对调）

以 baseUs=80us 为例：

```
offset=5  → 慢轮 +200us（速差 3.5x）
offset=15 → 慢轮 +600us（速差 8.5x）
offset≥25 → 慢轮 +1000us（速差 13.5x）
```

### 底盘物理量接口

```cpp
Cart.moveMm(300, 160);           // 前进 300mm, 160us/步
Cart.moveMm(-150, 240);          // 后退 150mm, 240us/步
Cart.rotateAngle(90, 160);       // 左转 90° (CCW)
Cart.rotateAngle(-180, 160);     // 右转 180° (CW)
Cart.trackForward(300000, 80);   // 前向循迹 300000 步
Cart.trackBackward(10000, 80);   // 后向循迹 10000 步
Cart.trackForwardMm(1000, 80);   // 前向循迹 1000mm（毫米单位，推荐）
Cart.trackBackwardMm(500, 80);   // 后向循迹 500mm（毫米单位，推荐）
```

精度依赖 `Config.h` 中的标定值：

- `WHEEL_STEPS_PER_MM`（≈29.10）— 直行距离换算
- `WHEEL_BASE_MM`（190.0）— 旋转角度换算（标定方法：转过量→增大，转不够→减小）

### 电机旁路模式

```
DEBUG_MOTOR_BYPASS=1
```

不驱动实际电机，只打印 `[MOTOR_BYPASS]` 日志。用于在脱离硬件时验证逻辑。

## 模块架构

```
Transport_Cart.ino        — 主入口 + 分阶段调试
├── Config.h              — 所有引脚定义和常量
├── Stepper.h/cpp         — 步进电机驱动（非阻塞）
├── LineSensor.h/cpp      — 12路灰度传感器 + 加权质心偏移量
├── Chassis.h/cpp         — 底盘状态机（直行/旋转/循迹/圆弧）
├── PushRod.h/cpp         — 电动推杆（L298N，伸/缩时长输入）
├── QRScanner.h/cpp       — 二维码扫描（Serial3 自动输出，CR分帧解析）
├── Turntable.h/cpp       — 转盘步进电机（72°旋转 + 5仓位管理 + 颜色识别定位）
├── ColorSensor.h/cpp     — TCS230 颜色识别（中断计数，非阻塞）
└── TaskFlow.h/cpp        — 正常模式任务流程编排（任务1+任务2）
```

## 正常模式

`MAIN_DEBUG=0` 时进入正常工作模式，`loop()` 反复调用 `TaskFlow_Update()`（其内部泵动各模块）。

当前流程为**任务2 + 任务1 骨架**（默认先2后1，规则允许自选顺序）：

- **任务2**：出HOME → 右二维码区扫码(1~6)（方案=3个摆放点上各是A/B/C哪个物块）→ **循迹前进**按 **点3→点2→点1** 顺序收满3块 → 一起搬运，按**固定规则** A→冠军台、B→亚军台、C→季军台 摆放3次 → 返回HOME
- **任务1**：出HOME → 左二维码区扫码(1~16) → **循迹前进**沿线收满5个彩色物块（物块在循迹路线上）→ 逐仓转180°识别颜色并记录 → 按方案放到中心目标区A~E → 返回HOME

所有运动原语（出HOME、去二维码区、循迹收料、去目标点、放料动作、返回HOME等 11 个）在 `TaskFlow.cpp` 中以 `TODO(用户)` 留空，需结合场地实测的定距移动/姿态调整参数填写。
