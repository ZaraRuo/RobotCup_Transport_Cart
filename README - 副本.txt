# RobotCup Transport Cart — 自动搬运机器人

基于 Arduino Mega 2560 的自动搬运机器人。支持黑线循迹、二维码导航、物品搬运等任务。

## 硬件清单

| 硬件 | 数量 | 说明 |
|------|:----:|------|
| Arduino Mega 2560 | 1 | 主控板 |
| 步进电机 + 驱动器 | 2 | 底盘后轮驱动，差速转向 |
| 步进电机 + 驱动器 | 1 | 转盘旋转（72°/144°/216°） |
| 灰度循迹传感器 | 12路 | 前8路 + 后4路，黑线检测 |
| 二维码扫描模块 | 1 | ADL615H，命令触发模式 |
| 电动推杆 + L298N | 1 | 货物推放 |

## 引脚分配

参见 [`Transport_Cart/Config.h`](Transport_Cart/Config.h)。

| 模块 | 引脚 | 说明 |
|------|------|------|
| 左轮步进 | DIR=30, PUL=11, EN=31 | 底盘左后轮 |
| 右轮步进 | DIR=32, PUL=12, EN=33 | 底盘右后轮（方向反转） |
| 转盘步进 | DIR=40, PUL=41, EN=42 | 货物转盘 |
| 前侧传感器 | A0~A7 | 8路，从左到右 |
| 后侧传感器 | A8~A11 | 4路，从左到右 |
| 推杆 L298N | IN1=22, IN2=23, ENA=24 | 推杆伸/缩/停止 |
| 二维码 Serial3 | TX=14, RX=15 | 9600bps |

二维码模块为命令触发模式，触发指令 `7E 00 08 01 00 02 01 AB CD`（写标志位 0x0002 bit0=1 启动一次扫码）。

## 接线指南

> 引脚编号均以 [`Config.h`](Transport_Cart/Config.h) 为准；Arduino Mega 2560 为 5V 主控，注意信号电平匹配。

### 1. 步进电机（左后轮 / 右后轮 / 转盘）

驱动器接口为 PUL / DIR / EN 三路信号。**EN 极性：HIGH=脱机（禁用），LOW=使能**（`Stepper::init()` 初始化为 LOW）。

| 电机 | DIR | PUL | EN | 说明 |
|------|-----|-----|-----|------|
| 左后轮 M1 | D30 | D11 | D31 | 底盘左后轮 |
| 右后轮 M2 | D32 | D12 | D33 | 底盘右后轮 |
| 转盘 | D40 | D41 | D42 | 货物转盘（72°倍数） |

- 右后轮无需改线：`Stepper_Init()` 已通过 `setDirInvert(true)` 在软件上反转方向。
- 电机电源（驱动器电源端）独立供电，电压按驱动器/电机规格选择（常见 12V），**必须与主控共地**。

### 2. 灰度循迹传感器（12路）

| 传感器 | Arduino 引脚 | 说明 |
|--------|-------------|------|
| 前侧 Q1~Q8 | A0~A7 | 从左到右排列，前进循迹 |
| 后侧 H1~H4 | A8~A11 | 从左到右排列，后退循迹 |

- 数字量输出：黑线上方为 `1`（`LINE_BLACK`），白底为 `0`（`LINE_WHITE`）。
- 传感器供电 5V，与主控共地。

### 3. 电动推杆（L298N）

| L298N 端子 | Arduino | 说明 |
|-----------|---------|------|
| IN1 | D22 | 方向控制（与 IN2 组合） |
| IN2 | D23 | 方向控制 |
| ENA | D24 | 代码初始化为 HIGH（全速使能） |
| OUT1 / OUT2 | — | 接推杆电机两根线 |
| 电源 VCC/GND | 独立电源 | 电压按推杆规格（常见 12V），与主控共地 |

方向逻辑（`PushRod.cpp`）：

| IN1 | IN2 | 动作 |
|-----|-----|------|
| HIGH | LOW | 伸出 |
| LOW | HIGH | 缩回 |
| LOW | LOW | 停止 |

### 4. 二维码扫描模块（ADL615H）

| 模块端子 | Arduino | 说明 |
|---------|---------|------|
| TX | D15（Serial3 RX） | 模块数据输出 → 主控 |
| RX | D14（Serial3 TX） | 主控触发指令 → 模块 |
| VCC / GND | 5V / GND | 波特率 9600，共地 |

- 命令触发模式：主控发送 `7E 00 08 01 00 02 01 AB CD` 启动一次扫码。
- 若模块 RX 为 3.3V 电平，需确认兼容 5V 逻辑或加电平转换。

### 5. 电源与共地要求

1. 所有模块（电机驱动、传感器、二维码模块）GND 必须与 Arduino GND 相连（共地）。
2. 电机/推杆使用独立电源，禁止从 Arduino 5V 引脚取电。
3. 上电顺序：先接好信号线与共地 → 再上电机/推杆电源 → 最后 USB 连接烧录调试。

### 6. 接线自检（对应调试阶段）

| 检查项 | 调试阶段 | 预期现象 |
|--------|:-------:|---------|
| 推杆伸缩 | 1 | 伸2s→缩1s→脉冲500ms，重复3次 |
| 传感器读数 | 2 | 串口每500ms输出12路值+偏移量 |
| 单电机转向 | 3 | 左/右轮各正转3000步+反转3000步 |
| 底盘直行 | 4 | 前进300mm→后退150mm→±90° |
| 二维码通讯 | 7 | 扫码后串口打印结果 |
| 转盘旋转 | 9 | 72°/144°/216° 往返 |

## 模块架构

```
Transport_Cart.ino         — 主入口 + 分阶段调试 + 正常模式
├── Config.h               — 引脚定义、系统常量
├── Stepper.h/cpp          — 步进电机非阻塞驱动
├── LineSensor.h/cpp       — 12路灰度传感器 + 加权质心偏移量
├── Chassis.h/cpp          — 底盘状态机（直行/旋转/循迹）
├── PushRod.h/cpp          — 电动推杆（L298N H桥）
├── QRScanner.h/cpp        — 二维码扫描（命令触发模式）
├── Turntable.h/cpp        — 转盘步进电机（72°倍数旋转）
└── TaskFlow.h/cpp         — 正常模式任务流程编排
```

## 车辆运动模型

```
          前 (行进方向)
          ┌─────────┐
          │ 万向轮  │ ← 无动力，仅支撑
          │         │
  ← 左    │  车 体  │    右 →
          │         │
     ┌────┤  ┌──┐   ├────┐
     │ M1 │  │  │   │ M2 │ ← 步进主动轮（后轮）
     └────┤  └──┘   ├────┘
          │    ↑    │
          │  190mm  │
          └─────────┘
```

| 参数 | 值 | 说明 |
|------|-----|------|
| 步距角 | 1.8° | 电机规格 |
| 细分数 | 32 | 驱动器设置 |
| 每圈步数 | 6400 | 360÷1.8×32 |
| 轮径 | 70mm | 后轮 |
| 每 mm 步数 | ≈29.10 | 6400÷(π×70) |
| 后轮轮距 | 190mm | 两主动轮中心距 |

### 旋转标定参考（基于 WHEEL_BASE_MM=190）

| 角度 | 每轮弧长 | 每轮步数 |
|------|---------|---------|
| 45° | 74.61mm | 2,171 |
| 90° | 149.22mm | 4,342 |
| 180° | 298.45mm | 8,684 |

1. 选择 **Arduino Mega 2560**
2. 验证 → 上传

## 调试模式

通过宏选择运行模式：

```cpp
#define MAIN_DEBUG          1    // 1=调试，0=正常（代码当前默认 1）
#define DEBUG_STAGE         5    // 调试阶段 (1~9)（代码当前默认 5）
#define DEBUG_MOTOR_BYPASS  0    // 1=电机旁路（只打日志）
```

### 调试阶段一览

| Stage | 名称 | 说明 |
|:-----:|------|------|
| 1 | 推杆测试 | 伸→缩→脉冲，重复3次 |
| 2 | 传感器读数 | 12路原始值 + 偏移量，每 500ms 输出一行 |
| 3 | 单电机测试 | 左轮/右轮独立正反转 |
| 4 | 底盘直行 | 前进300mm→后退150mm→±90°旋转 |
| 5 | 前向循迹 | 循迹前进 300000 步，测试修正参数 |
| 6 | 后向循迹 | 循迹后退 10000 步 |
| 7 | 二维码扫描 | 命令触发模式，扫码打印结果 |
| 8 | 原地旋转 | 45°/90°/180° CCW+CW，标定用 |
| 9 | 转盘测试 | 72°/144°/216° CCW+CW |

### 循迹修正算法

统一修正逻辑（前进/后退共用）：

- **线性比例修正**：偏移 ±25 内按比例递增
- **最大修正**：偏移 > 25 时直接满额修正
- 修正量通过 `TRACK_MAX_CORRECTION_US` 在 `Config.h` 中调参（默认 1000）

以下示例以 `baseUs=80us`（Stage 5 参数）计算：

```
offset=5  → 慢轮 +200us（速差 3.5x）
offset=15 → 慢轮 +600us（速差 8.5x）
offset≥25 → 慢轮 +1000us（速差 13.5x）
```

## 正常模式

`MAIN_DEBUG=0` 时进入正常工作模式，启动后按 `TaskFlow` 预编排的步骤执行任务流程。

当前 `TaskFlow` 仅含占位步骤（`STEP_IDLE`/`STEP_DONE`），实际任务流程待编排。
